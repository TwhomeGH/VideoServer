# 工作監看

登入後開啟「工作監看」。Video Node、Central 與 Transcode Worker 都提供目前服務的監看頁；閒置時每兩秒更新，有等待／執行中的影片工作時每半秒更新，背景分頁每五秒更新。CPU 與流量速率仍由後端每兩秒取樣，趨勢線只在新樣本到達時加入資料，保留最近 60 個樣本，離開或重新整理後重設。

## 工作狀態

Video Node 顯示影片匯入與重新讀取資訊的等待、執行、失敗及完成筆數。統計讀取完整佇列，不受「影片工作」最近 100 筆顯示上限影響；執行中的工作優先列出，再列最早等待的工作，合計最多 10 筆。

監看頁在寬螢幕使用兩欄：左側是目前影片工作，右側是儲存池掃描與自動補齊；CPU／記憶體／HTTP 四個指標在上方並排。900px 以下改為單欄，390px 也不產生水平捲動。掃描區會列出每個池的名稱、下次掃描與目前退避，不再只顯示全域摘要。

工作顯示目前階段與雜湊進度；可前往「影片工作」查看錯誤與重試。筆數代表目前各狀態的工作紀錄，不是歷次執行次數。重新探測同一影片沿用同一工作，嘗試次數會繼續累計。

工作頁與監看頁共用平順進度條；只有已收到的實際雜湊進度才顯示百分比，影片資訊檢查階段顯示活動動畫。完整排程順序見 [背景匯入說明](import-processing.md)。

自動掃描另顯示執行／排程狀態、週期、閒置退避上限及最近掃描結果；儲存池頁會顯示每池下次掃描、目前退避與「掃描此池」按鈕。自動補齊會顯示是否啟用、下次檢查倒數與待檢查候選數；預設關閉，開啟後只在整個佇列閒置時排一筆。Central 聯邦同步、遠端 Worker 派工尚未實作，不會顯示虛構的活動。

## 數據範圍

| 項目 | 含義 |
| --- | --- |
| 服務 CPU | 目前 DVN 程序的 CPU 時間差；單核心滿載為 100%，多核心可超過 100% |
| Go 記憶體 | Go runtime 的 HeapAlloc；「Go 保留」為 Sys，不等於完整程序常駐記憶體 |
| HTTP 傳送／接收 | 目前服務實際讀寫的本文位元組，提供累計及每秒速率 |
| HTTP 工作負載 | 處理中請求、完成速率、累計完成數與 5xx 回應數 |
| 執行環境 | 服務運行時間、邏輯 CPU、Go 平行上限與 Goroutine 數 |

CPU 與記憶體不包含 FFprobe／FFmpeg 子程序；Go 記憶體也不包含全部 SQLite／作業系統配置。流量包含影片播放、靜態頁面、登入、健康檢查與監看本身，不包含 HTTP 標頭、TLS、其他程序或所有網卡流量。處理中請求可能包含正在讀取此監看資料的請求。

Docker 中讀取的是目前容器內的 DVN 服務，不能當作宿主機總使用率。尚未提供容器配額百分比、宿主機記憶體、磁碟容量、網卡統計、跨服務彙整、告警或持久歷史。

資源計數在程序重啟後歸零；SQLite 中的影片工作保留。CPU 需要首次兩秒取樣完成後才有數值，無法取得時會顯示錯誤。頁面連線失敗時保留最後成功資料並標示更新失敗。

## API 與部署

`GET /api/v1/monitor` 使用既有管理員 session，未登入回應 401；不需要另開端口或部署監控資料庫。API 回應不快取，不保存請求內容或完整 URL。

Windows 與 Linux 已實作程序 CPU 讀取；其他平台會標示 CPU 無法取得，其餘項目仍可使用。更新 Docker 測試環境使用 `npm run testing:up`；原生開發重新啟動 `npm run dev` 即可。
