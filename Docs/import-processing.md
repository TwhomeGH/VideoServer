# 背景匯入與影片資訊

手動匯入與儲存池自動掃描都會建立持久工作。在「影片工作」查看最近 100 筆工作、處理階段、雜湊進度與錯誤；掃描排入工作並不表示影片已匯入完成。工作頁採緊湊列與每頁 20 筆，可依全部／處理中／失敗／完成篩選；路徑、錯誤與更新時間收在「詳細」展開。

工作依序執行 FFprobe、SHA-256 與索引寫入。保存片長、解析度、影音編碼、容器及影格率；FFprobe 只檢查可讀的影片資訊，不保證整段影片均可完整解碼。來源若於處理時變動，工作會失敗。

## 排程與進度

手動匯入、自動掃描匯入與重新讀取資訊共用單一背景執行器，一次只處理一部影片，避免同時讀取大量磁碟資料。等待工作依 `created_at`、工作 ID 排序，由較早建立者先執行；清單則以最近建立者在前顯示，兩種順序不同。

加入工作會喚醒執行器；完成一部後立刻檢查下一部，不會固定等待兩秒。兩秒定時器只是佇列閒置或查詢失敗後的補查。執行中的工作不會被新工作中斷，沒有手動優先權或多工設定。

同一影片等待／執行中的重新讀取請求會沿用原工作。已完成後再次重新讀取會重設排程時間，加入隊尾；失敗後按「重試工作」則沿用原建立時間，可能排在較新的等待工作之前。重啟恢復的未完成工作也沿用原時間，雜湊從頭計算。

後端計算雜湊時約每 250 毫秒保存一次進度。工作頁改用 `GET /api/v1/import-jobs` 單獨讀取狀態，不重新讀取影片庫或檢查來源檔案：工作事件透過 SSE 立即觸發更新；連線不可用時有活動每 500 毫秒、閒置每兩秒、背景分頁每五秒輪詢。畫面保留上一份資料，避免重新載入時閃爍。

雜湊進度條只在收到實際位元組數後，以 450 毫秒過渡呈現；不會按時間自行增加百分比。FFprobe 階段無可估算的總量，使用持續活動動畫。啟用系統「減少動態效果」時，動畫與平滑過渡關閉。小檔案可能在兩次讀取之間完成，不刻意延長動畫。

失敗工作不會由掃描自動反覆重建。修正來源或工具後，按「重試」沿用原工作與描述。重複手動匯入同一路徑會回應 409；已完成的影片請從影片庫編輯描述。

## FFprobe 安裝與設定

Video Node Docker image 已附 FFmpeg／FFprobe。原生執行請安裝 FFmpeg 並讓 `ffprobe` 可從 PATH 執行，或在基準 JSON 設定 `ffprobePath` 為執行檔完整路徑。

`probeTimeoutSeconds` 預設 60，可設定 1–3600 秒。這兩項目前需修改基準設定並重啟，未開放網頁覆寫。工具缺失或逾時會讓工作失敗，錯誤可在工作頁查看。SHA-256 讀取受 `hashLimitMiBps` 限制（預設 64 MiB/s，0 不限），大型檔案不會無上限佔用磁碟。

## 保存與恢復

SQLite schema v4 保存工作與影片技術資訊。背景工作逐筆執行；重啟後未完成工作會重新排入，雜湊從頭計算。影片、技術資訊與完成狀態在同一筆交易提交。

既有影片若缺少技術資訊，可在設定開啟 `autoBackfill` 後自動補齊（預設關閉）。補齊只處理「沒有任何 reprobe 工作記錄」的影片，一次一筆，且只在整個佇列閒置時排程；「閒置」包含手動匯入、掃描與手動重讀，只要有任何 queued／running 工作就會等待。有候選時才會排程；來源離線、大小或修改時間不符，以及曾經失敗的影片不會自動重試，請用「重新讀取影片資訊」或「重試工作」。目前沒有定期重新探測全部影片的排程。

每日自動補齊上限是 `backfillDailyLimit`（預設 50 部）與 `backfillDailyGiB`（預設 20 GiB），取先到者；`0` 不限，只限制自動補齊，手動重讀不受限。用量持久化並以服務本地日重置；Compose 預設 `TZ=Asia/Taipei`，達到上限後候選保留，隔日再排。監看頁可在上限用完時手動重設今日用量，需二次確認，只清今天。停用的儲存池不納入掃描、匯入或自動補齊；其影片索引保留，重新啟用後再處理。排程後可在「影片工作」與[工作監看](monitoring.md)查看進度與今日用量。

重新探測會驗證來源大小、修改時間與 SHA-256，確認仍是原索引的影片，再更新技術資訊。標題、描述、Tag、作者、影片識別與原始檔案均保留；處理期間編輯描述也不會被覆寫。來源離線、已變動或 FFprobe 失敗時，保留原有技術資訊並顯示工作錯誤。來源恢復後可重試。

同一影片重複排程會沿用同一筆重新探測工作；執行或等待中不新增重複工作，完成或失敗後可再排程。大型影片需要重新讀完整檔案驗證雜湊，並非立即完成。

這批尚未加入定期重新探測全部影片、封面擷取與轉碼。

## API

- `POST /api/v1/videos/import`：建立工作，回應 202 與工作資訊。
- `POST /api/v1/videos/{id}/probe`：以空 JSON 物件建立或沿用重新探測工作，回應 202；影片不存在回應 404。
- `GET /api/v1/library`：包含影片與最近 100 筆工作。
- `GET /api/v1/import-jobs`：只取得最近 100 筆工作，沒有工作時回應空陣列；適合工作頁更新。
- `GET /api/v1/import-jobs/{id}`：查詢單筆工作。
- `POST /api/v1/import-jobs/{id}/retry`：以空 JSON 物件重試失敗工作，回應 202。

以上 API 均需管理員登入。
